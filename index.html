Run history

    Every Run draws a new random robot. Replay runs one of these draws again with the current settings.

    Start pose

    Your code's setPose() placed the robot here (field coordinates, heading 0° = up the field), so these numbers follow the code.

    Code 0, 0, 0 is this pose. +y is the robot's forward, +x its right. Drag the dashed robot on the field to move it, the handle to turn it.

    Drivetrain
    Chassis wheels + tracking wheels

    Front of the robot is up. Click a wheel in the drawing to switch it between omni and traction. Wheel size is the wheel diameter above; the robot length and track width set where the wheels sit.

    Goal aligners hit the goals

    Goal base size, flat to flat (in)

    The goals are screwed to the field, so they never move: the robot (its body and its aligners) is stopped by them, slides along them with friction and is turned by them. A goal counts as aligned when any surface of it is within the aligner's tolerance of the aligner's alignment point. With real-life error on, the aligners grip a little harder and vary from run to run, so aligning is slightly less certain than in a perfect sim. The goal sizes are estimates (the game manual only shows them in a drawing): set them from Appendix A of the manual.

    Real-life error gyro drift + wheel slip

    On: every Run gives the robot a new random draw (its gyro has a bias, a turn-rate error and noise; the floor grip changes a little), so results vary from run to run like on a real field. How big the errors are comes from the Chassis above: traction wheels grip and slide less, tracking wheels keep the odometry right when the drive wheels slip. Changing a setting re-runs with the same draw. The odometry only sees the wheels and the gyro, so it slowly disagrees with where the robot really is. setPose() resets it, like a wall reset. Off: a perfect robot.
